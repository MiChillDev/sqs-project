
# Was lief gut

- Einigung auf Thema, Projektziel (Minimalprinzip)
- Einigung auf Tech-Stack
- Initialisierung von git, backend, frontend (funktioniert)
- Frühe Innitialisierung des backends und openAPI spec (hilfreich für FE)
- Erstellung von Issues
- Eigenständiges Arbeiten
- Setup von Actions
- Notwendiges Maß an Kommunikation
- Aufgabenverteilung (keine großen Überschneidungen oder Abhängigkeiten)
- Weekly an sich hilfreich
- Kein Overengineering

# Wo hat es gehakt

- Geschwindigkeit & Schätzung
- Weekly nicht immer alle anwesend
- Workload nicht exakt durch 3 geteilt (bisher)
- Styling im Frontend noch nicht klar (Farben etc.)
- Schätzung von verbleibenden Aufgaben (docs, Sonarcube, Erreichung von Testabdeckung) zu optimistisch geschätzt
- Keine ADRs festgehalten, kaum docs
- Me-Problems
  - GitHub restrictions
  - Testabdeckung, TDD

# Was sollten wir künftig anders machen? (Zusammentragen von Maßnahmen)

- Kurzes, effizientes wöchentliches Weekly? oder zumindest regelmäßiger Austausch
- Ralph: Docs setup aufsetzen, sodass jeder ab sofort Docs ordentlich festhalten kann
- Alle Bereiche möglichst frühzeitig initialisieren (verschiedene Tests, Feature-MVP)
- Bessere Aufteilung von Workload (nicht basierend auf 'wer ist repo owner', sondern z. B. Verfügbarkeit und Dringlichkeit)
